## 一、本版做了什么

### 1. UI：底栏九个页签合并为四个，新增功能侧栏

底栏从 9 项收敛为 **概览 / 功能 / 接口 / 关于** 四项，原来六个功能页
（屏幕 / 进程 / 文件 / 应用 / 解锁 / 诊断）全部收进「功能」页，在该页内用左侧竖排侧栏切换。

- 侧栏宽度**按窗口宽度自适应**：平板 132vp；手机（<600vp）92vp；超窄（<360vp）80vp，
  旋转或分屏时自动重算，不再占手机半屏；
- 侧栏选中项高度在窄屏降到 40vp，左右内边距 8vp，文字超长自动省略号；
- 内容区直接复用原有六个页面，布局与交互零改动，功能一个没删；
- 侧栏自身可滚动，系统字号调大后六项不会顶出屏幕；
- 侧栏切换只换内容区、不做整页淡出，连续切页不再每次等 110ms 动画；
- 六个子页仍是首次进入才拉数据（进程 / 文件 / 应用各自懒加载），切页不会一次打三条命令。

### 2. 概览页新增「快捷功能」入口

概览页在设备信息下方加了两行共六个快捷卡片（屏幕 / 进程 / 文件 / 应用 / 解锁 / 诊断），
点一下就是「切到对应子页 + 跳到功能页」，不用先点底栏再找侧栏。

### 2.5 新增「终端」子页（功能侧栏第 7 项）

- 输入一条命令 → 输出累积显示，等宽字体、可长按复制；
- **cwd 由页面自己维持**：纯 `cd xxx` 会用 `cd xxx && pwd` 反查真实路径，其它命令自动前缀
  `cd '<cwd>' 2>/dev/null;`，所以 `cd` 效果看起来是连续的（hdc 的 shell 是非交互 exec，本身不留状态）；
- 历史最近 50 条，界面只显示前 8 条，点一下回填输入框；
- 输出整块上限 200 KB，超出丢最早的部分；单条命令 30 秒超时；
- 执行身份 `uid=2000(shell)`，**不是 root**：读不到 `/data/app`、改不了系统分区；
- 不支持真交互程序（`vi`、`top` 跟随刷新），因为没有 PTY；这类需求仍走诊断页的固定用例。

### 2.6 `/v1/shell` 改为默认关闭

- 接口页新增「高危端点」开关，**默认关**；关着时该端点直接返回错误，`/v1/capabilities` 也不再列出 `shell`；
- 打开后每次调用都会写一条审计日志（时间 + 命令前 120 字符）；
- App 内的「终端」页不受这个开关影响，它是本地能力，不走 HTTP。

### 3. 修掉的 bug 与硬化项

| # | 问题 | 处理 |
|---|---|---|
| 1 | 版本号硬编码：界面上写着 `v1.2.0 · build 1002000`，与包内 1.2.1 / 1002001 不一致 | 改为 `bundleManager.getBundleInfoForSelfSync()` 实时读取，关于页、头部、`/v1/ping` 全部统一 |
| 2 | `/v1/ping` 协议里写死 `"version":"1.2.0"` | 同上，改为运行时读包信息，不再手写 |
| 3 | shell 参数用双引号拼接（`cat "…"`、`bm install -p "…"` 等 8 处） | 统一改为单引号 + `'\''` 转义的安全引用函数 `Gateway.q()`；路径或包名里带 `"`、`$`、反引号不再把命令拼歪 |
| 4 | API 网关 `Content-Length` 解析未校验，`parseInt` 返回 NaN 时静默按 0 处理、body 被截 | 显式判 `isNaN` / 负数，非法值归 0 |
| 5 | API 网关无请求体上限，本机客户端灌大包可吃内存 | 请求缓冲上限 3 MB，超限回 413；header 超 64 KB 直接断连 |
| 6 | 半截请求（只发 header 不发 body）或空连接会一直占着句柄 | 每个连接 15 秒兜底关闭 |
| 7 | 声明了 `GET_NETWORK_INFO` 但全工程无 `connection.*` 调用 | 已从 `module.json5` 移除，权限清单只留真正用到的 `INTERNET` |

### 4. 权限自查结论（"完全利用"口径）

- **保留**：`ohos.permission.INTERNET` —— `http` 请求、`socket` 回环连接、`openssl s_client` 都依赖它，实际使用。
- **移除**：`ohos.permission.GET_NETWORK_INFO` —— 声明但零调用，属于清单不诚实，移除后静态扫描面更小。
- **不需要声明**：`WRITE_IMAGEVIDEO`。截图保存走的是安全控件 `SaveButton` 的临时授权
  （`SaveButtonOnClickResult.SUCCESS` 才落盘），编译期那条 `To use this API…WRITE_IMAGEVIDEO` 是
  静态提示，不是缺陷，也不该为此申请受限权限。
- **不涉及**：`READ_PASTEBOARD`。剪切板两处都是 `createData` + `setData`（写），不触发读权限。

结论：本版声明的权限与代码实际调用**一一对应，无多申、无少申**。

## 二、安装步骤

本目录里的 HAP **未签名**，不能直接装机，必须先签名：

1. 用 HoKit（或 DevEco 的自动签名）对 `release/StarPivot-v1.2.1-r4-unsigned.hap` 签名；
2. 签名产物用 `hdc install -r` 装到设备，或直接在 HoKit 里点安装；
3. 装完先看头部副标题有没有 `· r4`，没有就是装错了文件；
4. 首次打开若提示"未连接"，在概览页按一下重连，确认顶部出现设备名（如 `本机 · SLG-W50`）。

## 四、已知限制（如实列出，未修）

1. **未签名**：本目录的 HAP 为 unsigned，签名由你在本地完成。
2. **应用图标仍是首字色块占位**，未替换为正式图标。
3. **接口页的 `selfTestApi()` 从未真实执行过**，接口自检按钮只保证 UI 可点。
4. **`/v1/shell` 默认关闭**，需要到「接口」页手动打开；这是有意设计的安全默认值，不是缺陷。
5. **v28.1 引入的 5 条端点**（`net.http` / `device.cpufreq` / `device.cluster` / `app.shared` / `app.patch`）经代码实现但未逐条做过真实 HTTP 调用验证，参数以 `docs/接口调用.md` 与源码为准。
6. **targetSdkVersion 未显式配置**，构建时有一条 hvigor 提示；本次未改动，避免影响运行期行为。
7. **界面已在 MatePad 11.5 S 实机确认**（底栏四项、功能侧栏、终端页、接口页开关均可见）；**手机窄屏（<600vp）的自适应侧栏宽度只做了逻辑实现，未在手机真机目视验收**。
