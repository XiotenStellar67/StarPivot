# 常见问题（FAQ）

## 一、设备连不上

**1. `hdc list targets` 输出 `[Empty]`**

按顺序排查：

1. 数据线是否支持传输（换一根试，这是最常见原因）；
2. 设备是否开了 **USB 调试**，插线后设备上有没有弹出「允许 USB 调试」——没弹就拔插一次、或关掉再开 USB 调试；
3. 电脑的设备管理器里有没有「未知设备 / 叹号」，有就装华为手机助手或换 USB 口；
4. Windows 上重开 hdc 服务：`& $hdc kill` 再 `& $hdc start`；
5. 还是不行，试试 `& $hdc list targets -v` 看详细状态。

**2. 设备开了调试，但显示 `unauthorized`**

设备端没有点「允许」。在设备上确认弹窗并勾选「始终允许」；没有弹窗就把 USB 调试关掉再打开。

**3. 应用内一直显示「未连接」，但 `hdc list targets` 正常**

App 用的是**本机直连 hdcd**，不走你在电脑上那个 hdc。也可能是 hdcd 端口变了：

1. 「概览」页点「启动（已连接，点此重连）」重试；
2. 仍然不行就切到 PC broker 方案（见下一条）；
3. 诊断页能看到 `hdcd 端口` 探测结果，若为空说明没探到端口。

## 二、PC broker 方案

**4. 什么时候需要 broker？**

本机直连 hdcd 在部分机型 / 部分系统版本上不可用（hdcd 未监听回环、或握手被拒）。这时用电脑当中间人：

```powershell
cd pc-broker
node broker.js
```

电脑需满足：已装 DevEco（有 `hdc`）、`hdc list targets` 能看到设备、电脑防火墙允许本机回环。

**5. broker 起来了但 App 还是未连接**

1. 确认 broker 日志里出现了 `rport established`；
2. 电脑上的 hdc 版本要和设备匹配（用 DevEco 自带的那个）；
3. App「接口」页把连接模式切成 `pc`（若界面上有该选项）后重连。

## 三、编译与签名

**6. `构建失败：未产出 HAP`**

先看完整日志最后 20 行，最常见的三类：

- `未找到 DevEco Studio` → 设 `$env:DEVECO_HOME`；
- Java 相关崩溃（`0xC0000409`）→ PATH 里的 JDK 不是 DevEco 自带的，用 `build.ps1` 会自动处理；
- ArkTS 语法错误 → 日志里会指明 `文件:行号`。

**7. 安装失败，提示签名相关错误**

说明包的签名 / profile 与设备不匹配。常见原因：

- 用的是别人的签名或旧 profile；
- profile 里的 UDID 不包含当前设备 → 重新做一次自动签名（会写入当前设备）；
- 包被改过（重新签名后又被修改）。

**8. 安装失败，提示版本低于已安装版本**

设备上已装的包 versionCode 更大。处理：先卸载旧版再装，或把新包的 versionCode 调大后重新签名。

**9. `install failed due to grant request permissions failed`**

包申请的权限与 profile 里允许的权限不一致。本项目只申请 `INTERNET`（普通权限），正常不会触发；
如果你自己加了受限权限，需要在 profile 里同步声明。

## 四、运行期

**10. 截屏 / 点按没反应，返回错误**

1. 先确认顶部是「已连接」；
2. `snapshot_display` 在锁屏状态下可能失败，先亮屏解锁；
3. 部分机型对 `uitest` / 注入有限制，换用「按键」或「文本输入」测试。

**11. 终端里执行命令返回 `Permission denied`**

这是 DAC 权限隔离的**正常结果**：`shell` 用户读不到别的应用私有目录、改不了系统分区。
它不代表程序有 bug，也不代表拿到了 root。

**12. 终端里 `top` / `vi` 卡住或没有持续刷新**

终端是「一条命令一次执行」，没有 PTY，不支持交互式/持续刷新的程序。
需要看进程实时状态请用「诊断」页的固定用例，或 `ps`、`hidumper --cpuusage` 这类一次性输出。

**13. 网关开了，但 curl 返回 401**

请求头少了 `X-StarPivot-Token`，或令牌不对（令牌在「接口」页，可一键复制）。

**14. 网关启动失败，提示端口可能被占用**

换一个端口（接口页端口输入框），例如 18795，再打开开关。

**15. `/v1/shell` 一直报「未开启」**

这是设计如此：`/v1/shell` 默认关闭，需要在「接口」页的「高危端点」开关里手动打开。
App 内的「终端」页不受此开关影响。

## 五、其它

**16. 换手机 / 换平板后装不上**

自动签名的 profile 绑定了原设备 UDID，重新执行一次「自动签名」即可。

**17. 卸载重装后要重新配对吗**

要。hdcd 握手用的密钥存在本应用 preferences 里，卸载即清空；重新打开 App 会自动重新生成并握手。
「解锁」页的 PIN 同样会被清空，需要重新填。

**18. 项目能商用吗**

看 `LICENSE`（MIT）。但请注意：本项目只是把 `shell` 能力包装出来，**不提供任何绕过系统安全机制的能力**，
用于他人设备前必须取得设备所有者授权。

## 六、怎么看日志 / 怎么调试

**19. 应用白屏、闪退，或某个按钮没反应**

三个地方按顺序看：

1. **DevEco 的 Log 窗口**：Run 起来后底部有 `Log` / `HiLog` 标签，筛选 `Starpivot` 或
   `com.starpivot.xs`，ArkTS 报错和崩溃栈都在这里；
2. **App 内的「概览 → 运行日志」**：只有 20 条，记录连接、网关启停、读取动作；
3. **系统侧日志**：`& $hdc shell hilog -x -z 200`（看最近 200 行），
   崩溃记录在「诊断」页也能看到（走 `hidumper -e`）。

**20. 想确认某个能力到底有没有权限**

在「功能 → 终端」里直接跑：

```sh
id                       # 看当前 uid，应为 2000(shell)
ls -l /data/app/el1/bundle/public    # 预期 Permission denied
param get const.product.model        # 预期能读到机型
```

`Permission denied` 是权限隔离生效的证据，不是程序坏了。

**21. 改了代码之后怎么重新出包**

```powershell
.\build.ps1            # debug
.\build.ps1 -Release   # 正式包
```

然后按 `docs/快速开始.md` 第 5、7 步重新签名安装。只改了 `Index.ets` 这类源码时，
增量编译通常 1~2 分钟内完成。

**22. 端口 / 令牌 / PIN 存在哪，能不能清掉**

都存在本应用的 preferences（键值存储）里：

- 网关端口、开关状态、令牌：接口页可改；
- hdcd 配对密钥、端口：卸载重装会重新生成；
- 解锁 PIN、延时、间隔：解锁页可改。

想彻底清空，直接卸载应用再装。
